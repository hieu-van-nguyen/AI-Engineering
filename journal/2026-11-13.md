# Day 2 and 3: async HTTP, Pydantic models, pathlib and context managers

- Time spent:
- What I did:
  - **Async HTTP** — wrote `m1-foundations/fetch_many.py`: 20 URLs fetched with `httpx.AsyncClient`, concurrency capped by `asyncio.Semaphore`, run through `asyncio.gather(..., return_exceptions=True)`, with a summary (successes, failures, total time, average per request). It runs its own small local server (0.5 s delay, some URLs return 500 on purpose), so no outside site gets hit.
  - Ran it with semaphore limits 1 / 5 / 20: 10.31 s / 2.10 s / 0.58 s. Recorded in `notes/async.md`.
  - Added a simple retry (2 attempts, short delay) to `fetch_one.py` and `fetch_many.py`. Only timeouts, connection errors and 5xx are retried; a 4xx fails right away.
  - **Pydantic** — wrote `m1-foundations/pydantic_basics.py`: a `Ticket(BaseModel)` with `id`, `title`, `priority: Literal["low","medium","high"]` and `tags`. Validated good data, caught `ValidationError` for a wrong type, a missing field and an invalid priority (printing `e.errors()`), did a JSON round-trip with `model_dump_json()` / `model_validate_json()`, and added a `field_validator` that rejects a blank title.
  - **pathlib + context managers** — wrote `m1-foundations/files_and_context.py`: builds `data/sample.txt`, creates the folder with `mkdir(parents=True, exist_ok=True)`, writes, reads and lists `*.txt` with `glob`. Wrote a timer context manager two ways: a `Timer` class with `__enter__`/`__exit__` and a `@contextmanager` generator. All file I/O goes through `with open(...)` or `read_text()`/`write_text()`.
- What broke / what confused me:
  - A plain `python -m http.server` answers almost instantly, so the semaphore limit barely changes the timing. An artificial delay on the server side was needed to see the difference.
  - Where to sleep during a retry: sleeping while holding the semaphore wastes a slot, so each attempt takes the semaphore on its own and the delay happens outside it.
  - Pydantic quietly turned `"2"` into `2` for `id` (lax mode), so a "wrong type" test needs something that can't be converted, like `"abc"`.
  - mypy rejected `-> bool` on an `__exit__` that always returns `False`; it wants `Literal[False]`, because `bool` suggests it might swallow exceptions.
  - `sample.txt` read back as 84 characters but is 88 bytes on disk: on Windows, text mode writes each `\n` as `\r\n`.
- What I learned (1–3 bullets):
  - The semaphore doesn't make a single request faster; it controls how many wait at once, so total ≈ ceil(N / limit) × latency. `return_exceptions=True` keeps one failure from cancelling the batch, and retries should only cover errors that might go away (timeouts, connection errors, 5xx).
  - Pydantic reports every problem at once in `e.errors()`, each with `type`, `loc`, `msg` and `input`; a `field_validator` raising `ValueError` shows up there as `value_error`.
  - A context manager's exit code must run even when the block raises: `__exit__` always runs, and in a `@contextmanager` the code after `yield` needs `try/finally`. Returning `False` from `__exit__` lets the exception propagate.
